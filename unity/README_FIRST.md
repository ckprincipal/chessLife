# Stale-Mate — Unity 6 Starter v0.1 (presentation-only)

**Important:** This project IS a real Unity 6 project scaffold and contains a native C# 2D board **viewer**. It is **NOT** a completed Unity port of the Stale-Mate v0.5.8 game. It does not execute gameplay commands, fight, recruit, level, save, run AI, or provide authoritative fog. Do **not** treat it as a substitute for the fully playable standalone HTML.

The only authoritative, actually exercised rules implementation remains `Stale-Mate_v0.5.8_Play.html` plus the JS engine source in the separate v0.5.8 Source ZIP.

## Open and inspect in Unity

1. Install Unity Hub and a compatible **Unity 6.3 LTS** Editor through Unity Hub.
2. Extract this ZIP to any local folder. In Unity Hub, click **Add project from disk** and select the extracted `Stale-Mate_Unity_Starter_v0.1` folder.
3. Wait for the Editor to import it. Use **Tools → Stale-Mate → Create Bootstrap Scene**. This creates `Assets/Bootstrap.unity` and adds it to Build Settings.
4. Press **Play**. The native `StaleMateBootstrap` component is created automatically and renders the 50×50 starting board from **JS-engine-generated** fixtures.
5. Click **Traditional / Middle / Flatten** to compare formations, scroll to zoom, drag to pan, click a visible piece to inspect its type.
6. To test an export, use Unity's normal Build Profiles/Build Settings after creation of the Bootstrap scene. This build has **not** been executed in this environment.

The included opening snapshots are generated by `export_stalemate_unity_fixtures.js` from the exact working v0.5.8 JS engine. White-side fog visibility in the Unity viewer uses its recorded starting sight. These are **read-only snapshots**, not a network-secure multiplayer fog implementation.

## What is and isn't included

**Present:** Unity project (`Assets/`, `Packages/`, `ProjectSettings/`), C# runtime viewer, Editor scene-creation menu, deterministic starting fixtures for the three organizational structures, integration plan, scope and license notes. Nothing relies on paid plugins or imported art.

**Not present:** ported C# move/attack/fog state machine; 99-level XP/skills; multi-turn construction; training queues; AI; exact JSON save migration; verified Unity desktop/mobile/web builds. No Unity Editor executable was available to compile or run these C# files here. This is a **foundation**, not an assurance of functioning player interaction or cross-platform output.

## The safer port strategy

Keep the JS game as a golden executable reference. Port one deterministic rules area at a time into C#, and require exact matching outputs from the same seed and command trace before retiring the JS behavior. Suggested order: state serialization and deterministic RNG → movement and occupancy → combat and king capture → CP/turns → fog memory → XP/skills → construction and queues → AI → platform input and polish.

See `Docs/PORT_PLAN.md`, `Docs/LICENSING_NOTES.md`, and the v0.5.8 release notes in the separate source archive.
